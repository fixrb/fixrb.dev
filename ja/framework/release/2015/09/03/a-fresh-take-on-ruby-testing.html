Rubyのテストを新たな視点で

2015年9月3日 · Cyril Kato

Fix 1.0より前に公開した記事の翻訳です。記事は書かれたときのまま残しており、例は以前のバージョンのgemを指していることがあります。Fix 1.0についてはガイドをご覧ください。

今日、Fix 0.7のリリースをお知らせできることは、私たちの歩みにとって胸の躍る節目です。何か月にもわたる丁寧な開発と何度もの試行錯誤を経て、Rubyのテストにシンプルさと明快さを取り戻すテストフレームワークを、誇りをもってお届けします。

Fixの背後にある考え方

Fixは、ひとつの単純な観察から生まれました。テストフレームワークは、それがテストするコードより複雑であってはならない、ということです。わずか148行のコードで作られ、期待のライブラリSpectusに支えられたFixは、意図してミニマルな方法をとっています。ベンチマークやモックのような機能はあえて省き、最も大切なこと、つまり明快で保守しやすい仕様を書くことに集中しています。

主な特徴

  • 純粋な仕様の文書：Fixはspecを、ロジックをもたず、きわめて明快な、生きた文書として扱う
  • バージョンの変化に強い：仕様はFixのバージョンをまたいで安定しており、ソフトウェアの劣化から守られる
  • 魔法なし：振る舞いを見えにくくするモンキーパッチなど、Rubyの「手品」を避ける
  • 本物のRubyオブジェクト：手を加えていない純粋なRubyオブジェクトを扱い、曖昧さのない構造化されたspecを書ける

なぜまた新しいテストフレームワークなのか？

Rubyで10年開発してきて、私はRSpecのソースコードを理解するのに苦労している自分に気づきました。これは気がかりな問いを投げかけます。テストフレームワークがそれがテストするコードより複雑なら、私たちはどこまで自分のテストを信頼できるのでしょうか？

示唆に富む例を見てみましょう。

class App
  def equal?(*)
    true
  end
end

require "rspec"

RSpec.describe App do
  it "is the answer to life, the universe and everything" do
    expect(described_class.new).to equal(42)
  end
end

これをRSpecで実行すると：

$ rspec wat_spec.rb
.

Finished in 0.00146 seconds (files took 0.17203 seconds to load)
1 example, 0 failures

驚いたことに、RSpecはApp.newが42に等しいと言います！　この問題自体は実際の値と期待値を入れ替えることで解決できますが、複雑なテストフレームワークに潜む危険を浮き彫りにしています。

Fixの実際

Fixが実際のテストケースをどう扱うかを見てみましょう。

# car_spec.rb
require "fix"

Fix :Car do
  on :new, color: "red" do
    it { MUST be_an_instance_of Car }

    on :color do
      it { MUST eql "red" }
    end

    on :start do
      it { MUST change(car, :running?).from(false).to(true) }
    end
  end
end

# Running the specification
Fix[:Car].test { Car }

Fixが次のようにしていることに注目してください。

  • 仕様を明快で簡潔に保つ
  • メソッドの連鎖で自然に読めるようにする
  • 実装の詳細ではなく振る舞いに焦点を当てる
  • 種類の異なるテストでも一貫した構文を保つ

これから

バージョン1.0.0に向けて、私たちが重視するのは新しい機能を加えることではなく、安定と洗練です。Fixは本番で使える状態にあり、Rubyのコミュニティがそれをどう活用するのかを楽しみにしています。

重点を置く分野

  1. ドキュメントの充実：初めての人が始めやすくする
  2. パフォーマンスの最適化：Fixを軽く速いままに保つ
  3. コミュニティからのフィードバック：実際の使われ方を取り入れる
  4. エコシステムの成長：中核のフレームワークの周りにツールと拡張を作る

参加するには

  • プロジェクトでFixを試す：gem install fix
  • GitHubのリポジトリを見る
  • フィードバックを寄せる。どんな視点も歓迎します！

気に入っても、改善の余地があると思っても、ぜひ声を聞かせてください。あなたのフィードバックが、Fixの未来を形づくる助けになります。

楽しいテストを！
