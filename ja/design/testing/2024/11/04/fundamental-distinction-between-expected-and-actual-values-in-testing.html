テストにおける期待値と実際の値の根本的な違い

2024年11月4日 · Cyril Kato

Fix 1.0より前に公開した記事の翻訳です。記事は書かれたときのまま残しており、例は以前のバージョンのgemを指していることがあります。matchi 6については決めるのは期待値をご覧ください。

自動テストにおける期待値と実際の値の区別は、単なる慣習ではありません。注目に値する、設計上の根本的な原則です。

この2つの値の意味の違いを際立たせるには、期待値が既知の定数であり、仕様の欠かせない一部であることを理解しなければなりません。それに対して実際の値は、外部のオブジェクトを試して得られるもので、述語によって期待値に照らして評価されなければなりません。それこそが述語の役割です。得られた値が、期待値の定める基準を満たすことを確かめるのです。

この区別はあまりに根本的なので、述語の設計そのものの中で守られなければなりません。述語は初期化のときに期待値を基準として受け取り、その基準に照らして実際の値を評価します。値の扱いのこの非対称性は、2つの値の性質が根本から異なることを映しており、Matchiのような現代のテストライブラリが賢明にも取り入れている原則です。

この原則を具体例で示しましょう。2つの文字列の単純な同値性のテストを考えます。

EXPECTED_VALUE = "foo"
actual_value = "bar"

一見すると、この2つのやり方は同じに見えます。

EXPECTED_VALUE.eql?(actual_value) # => false
actual_value.eql?(EXPECTED_VALUE) # => false

しかし、この見かけの対称性は人を欺くことがあります。実際の値が細工されている場合を考えてみましょう。

def actual_value.eql?(*)
  true
end

actual_value.eql?(EXPECTED_VALUE) # => true

この例は単純化したものですが、根本的な原則を浮き彫りにします。述語は決して実際の値を信頼してはなりません。比較の責任を実際の値に委ねることは、それ自身の評価をそれに任せることになります。だからこそ述語は、期待値を基準として実際の値を評価し、その逆ではない形で、常に比較の主導権を握っていなければならないのです。

述語の設計へのこの厳密な姿勢は、テストの堅牢さだけでなく、その明快さと長期的な保守性にも役立ちます。
