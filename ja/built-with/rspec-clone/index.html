RSpec clone

RSpecの言葉を、約250行で。Fixrbのライブラリの上に。

RSpec cloneは、RSpecの言葉を話す小さなテストフレームワークです。describe、context、it、its、let、subject、before、expect、is_expected、pendingと、いくつかのマッチャーだけを備えています。Fixrbのgemではなく、Fixrbの作者Cyril Katoによる別のプロジェクトで、本拠はそのリポジトリです。ここで紹介するのは、その作りのためです。spectusがすべての期待を判定し、matchiがすべてのマッチャーを提供し、defiがitsのメソッドを送ります。いずれも、Fix 1.0を支えるライブラリです。残る仕事、つまりRSpecの言葉を書くのに必要だったのは、約250行でした。

インストール

Gemfileにgem "r_spec-clone"を加えるか、gem install r_spec-cloneを実行し、require "r_spec"してください。

ひとつのファイルで

specファイルはr_specをrequireし、そのexampleはファイルの読み込みとともに、書かれた順に実行されます。覚えるコマンドはありません。rubyがファイルを実行します。トップページと同じくアヒルを、今度はRSpecの言葉で書いてみます。

require "r_spec"

# A duck, in the words of RSpec.
class Duck
  def walk = "Klop klop!"
  def swim = "Swoosh..."
end

RSpec.describe Duck do
  subject { described_class.new }

  its(:walk) { is_expected.to eq "Klop klop!" }
  its(:swim) { is_expected.to eq "Swoosh..." }

  context "when asked to speak" do
    its(:speak) { is_expected.to raise_exception NoMethodError }
  end

  it "walks before it swims" do
    expect(subject.walk).to match(/Klop/)
    expect { subject.swim }.not_to raise_exception StandardError
  end

  pending "flies"
end

ruby duck_spec.rb
duck_spec.rb:12: Success: expected "Klop klop!" to eq "Klop klop!"
duck_spec.rb:13: Success: expected "Swoosh..." to eq "Swoosh..."
duck_spec.rb:16: Success: expected #<NoMethodError: undefined method 'speak' for an instance of Duck> to raise exception NoMethodError
duck_spec.rb:20: Success: expected "Klop klop!" to match /Klop/
duck_spec.rb:21: Success: expected "Swoosh..." not to raise exception StandardError
duck_spec.rb:24: Pending: flies

期待ごとに1行です。書かれた場所、判定、そしてspectusのサマリーが並びます。判定するものが同じなので、Fixと同じレポートになります。contextは子プロセスで実行されました。itsは期待の中でspeakを送ったので、そこで発生した例外を期待できました。pendingは1行を書いただけで、何も実行していません。すべての期待が満たされたので、ファイルは0で終了します。満たされない期待があれば、最初のひとつで実行は終了ステータス1で止まります。その先は、誤った前提の上で実行されることになるからです。

省いたもの

RSpecは大きなフレームワークで、毎日使っていて気持ちのよい道具です。cloneはその言葉を借り、残りは意図して省きました。省いたものがひとつ増えるたびに、specファイルを読む前に知っておくべきことがひとつ減ります。

  • モンキーパッチは一切なく、at_exitフックから実行されるものもありません。rspecコマンドも、フィルターも、ランダムな実行順も、フォーマッターもありません。
  • letとsubjectはただのメソッドで、使うたびに呼ばれます。メモ化はしません。
  • フックはbeforeだけです。afterもaroundもありません。
  • contextは子プロセスで実行されます。そのexampleがRubyのプロセスに加えた変更は、そこにとどまります。
  • 比較を受け取るのは期待値のほうです。==について嘘をつく実際の値は、合格できません。
  • 満たされない期待があれば、最初のひとつで実行が止まります。

すべての違いはREADMEにあり、RSpecにあるものの代わりに何を書くかは、wikiのComing from RSpecにあります。RSpec cloneは独立したプロジェクトで、RSpecの一部ではなく、RSpecチームの公認でもありません。その言葉を借りているRSpecチームに感謝します。

どう作られているか

cloneの期待は、ライブラリへのいくつかの呼び出しにすぎません。expect { … }.to(matcher)は、ブロックとともに呼ばれるSpectus.must(matcher)で、not_toはSpectus.must_notです。どの期待もMUST、つまりFixの3つのレベルの最初のものです。eq、be_nil、matchなどは、それぞれmatchiのマッチャーを組み立てます。itsはメソッドをdefiに渡し、defiがブロックの中でそれをサブジェクトに送ります。cloneを使わずに書くと、3つの期待はこうなります。

require "defi"
require "matchi"
require "spectus"

# expect { "foo".upcase }.to eq "FOO": a matcher of Matchi, in a MUST of
# Spectus, called with the block.
upcase = Spectus.must(Matchi::Eq.new("FOO")).call { "foo".upcase }
upcase.to_s # => "Success: expected \"FOO\" to eq \"FOO\""

# expect("foo").not_to be_nil: a MUST NOT.
present = Spectus.must_not(Matchi::Be.new(nil)).call { "foo" }
present.to_s # => "Success: expected \"foo\" not to be nil"

# its(:size) { is_expected.to eq 3 }, on "foo": Defi sends the method inside
# the block, so that what it raises can be judged too.
size = Defi::Challenge.new(:size)
sized = Spectus.must(Matchi::Eq.new(3)).call { size.to("foo").call }
sized.to_s # => "Success: expected 3 to eq 3"

cloneが加えるのは言葉です。グループはクラスで、入れ子のグループはそのサブクラスです。letはプライベートメソッドを、beforeはモジュールを定義します。exampleはインスタンスで、そこではexpectやマッチャーが語になります。contextはforkします。判定、マッチング、レポートの言葉はライブラリのもので、Fixも同じものを使っています。一方で直したものは、両方で直ります。cloneは2021年に、Fixrbの別のライブラリであるtest_tubeとexpresenterの上に最初に作られ、バージョン2.0でFix 1.0のエンジンの上に作り直されました。

RSpec cloneか、Fixか

どちらも同じように判定します。違うのは、テストファイルとは何か、です。cloneでは、RSpecと同じく、ファイルはひとつのサブジェクトを記述します。exampleはクラスを名指しし、それを組み立て、それに何かを期待します。どの期待も必須です。Fixでは、仕様はクラスを名指ししません。一度書けば、どんなサブジェクトに対してもテストでき、何が必須で、何が推奨で、何が任意かを述べます。驚きのない小さなランナーでRSpecの習慣を続けたいならcloneを、振る舞いに独立した文書がふさわしいならFixを選んでください。

両者は一緒にも使えます。Fixの仕様はmatchi-fixを通じてマッチャーになり、toはどんなマッチャーでも受け取ります。パラメーターをとるletが、それに語を与えます。

require "r_spec"
require "matchi/fix"

# What a duck does, as a specification of Fix.
Fix :Duck do
  on :walk do
    it MUST eq "Klop klop!"
  end

  on :speak do
    it MAY eq "Quaaaaaack!"
  end
end

Duck = Struct.new(:walk)

RSpec.describe "A specification of Fix, as a matcher" do
  let(:fix) { |name| Matchi::Fix.new(name) }

  it { expect(Duck.new("Klop klop!")).to fix(:Duck) }
  it { expect(Duck.new("Clank!")).not_to fix(:Duck) }
end

ruby fix_spec.rb
fix_spec.rb:20: Success: expected #<struct Duck walk="Klop klop!"> to fix Duck
fix_spec.rb:21: Success: expected #<struct Duck walk="Clank!"> not to fix Duck

仕様はアヒルが何をするかを述べ、specファイルはどのオブジェクトがアヒルかを述べます。
