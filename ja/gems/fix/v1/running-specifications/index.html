仕様を実行する

ファイルはrubyで、プロジェクトはfixで。そして、満たされたかどうかを伝える終了ステータス。

  1. ファイル
  2. プロジェクト
  3. ランダムな順序
  4. 環境
  5. データとしての結果

このページでは、3つの仕様ファイルからなるプロジェクトを実行します。2つは満たされ、1つは満たされません。

ファイル

仕様ファイルは、サブジェクトのテストで終わるRubyのプログラムです。testは期待ごとに1行を書き、すべてが成功したかどうかを返します。exitはそれをプロセスの終了ステータス、0か1にします。複数の仕様をテストするファイルは、fix/shapes_fix.rbのように、すべてをテストしてから一度だけexitします。

require "fix"

Square = Data.define(:side) do
  def area = side * side
end

Circle = Data.define(:radius) do
  def area = Math::PI * radius**2
end

Fix :Square do
  on :area do
    it MUST eq 4
  end
end

Fix :Circle do
  on :area do
    it MUST be_within(0.01).of(3.14)
  end
end

results = [
  Fix[:Square].test { Square.new(side: 2) },
  Fix[:Circle].test { Circle.new(radius: 1) }
]

exit(results.all?)

ruby fix/shapes_fix.rb
fix/shapes_fix.rb:13: Success: expected 4 to eq 4
fix/shapes_fix.rb:19: Success: expected 3.141592653589793 to be within 0.01 of 3.14

exit(…)の括弧は省かないでください。exit Fix[:Square].test do … endと書くとブロックはexitに渡り、testはブロックがないためにArgumentErrorを発生させます。

プロジェクト

fixコマンドは、fixディレクトリ以下の任意の深さにある、名前が_fix.rbで終わるファイルを名前の順に、それぞれ専用のプロセスで、fixを実行しているRubyで実行します。各ファイルの出力をそのまま通し、最後に満たされたファイルの数を示します。

fix
fix/shapes_fix.rb:13: Success: expected 4 to eq 4
fix/shapes_fix.rb:19: Success: expected 3.141592653589793 to be within 0.01 of 3.14
fix/tax_fix.rb:5: Failure: expected 20.0 to eq 20
fix/text/slug_fix.rb:6: Success: expected "hello-world" to eq "hello-world"
3 files, 1 not met: fix/tax_fix.rb

満たされなかったファイルはfix/tax_fix.rbです。

require "fix"

Fix :Tax do
  on :*, 0.2 do
    it MUST eq 20
  end
end

exit(Fix[:Tax].test { 100 })

100 * 0.2はFloatの20.0で、eq 20ではありません。引数にファイルやディレクトリを与えると、実行をそれらに絞り、与えた順に実行します。

fix fix/text
fix/text/slug_fix.rb:6: Success: expected "hello-world" to eq "hello-world"
1 file met

fixの終了ステータスは、すべてのファイルが満たされれば0、満たされないファイルがあれば1（読み込み時に例外を発生させたファイルや、異常終了したプロセスも含みます）、存在しないパスなど使い方の誤りなら2です。fix --helpでオプションの一覧が表示されます。

ランダムな順序

各ファイルはひとつのプロセスで、各コンテキストはその子プロセスです。サブジェクトがプロセスの中で変えたものは、ほかのファイルには届きません。外で、つまりデータベースやファイルで変えたものは届きます。--randomはファイルをランダムな順で実行し、最初に、同じ順でもう一度実行するためのコマンドを書きます。

fix --random
fix --random=2
fix/text/slug_fix.rb:6: Success: expected "hello-world" to eq "hello-world"
fix/tax_fix.rb:5: Failure: expected 20.0 to eq 20
fix/shapes_fix.rb:13: Success: expected 4 to eq 4
fix/shapes_fix.rb:19: Success: expected 3.141592653589793 to be within 0.01 of 3.14
3 files, 1 not met: fix/tax_fix.rb

ある順では満たされ、別の順では満たされないファイルは、ほかのファイルが残していったものに依存しています。

環境

プロセスはfixの環境を受け継ぎます。Gemfileのあるプロジェクトでは、bundle exec fixがすべてのファイルにバンドルのgemを与えます。RUBYOPT=-w fixはファイルを警告つきで実行し、RUBYOPT=-Ilib fixはlibのファイルを名前でrequireできるようにします。

終了ステータスを読めるものなら、何からでもFixを実行できます。Rakefileのタスクtask(:fix) { sh "fix" }は、満たされないファイルがあれば失敗します。GitHub Actionsのワークフローのrun: bundle exec fixのように、それを実行するCIのステップも同じです。

データとしての結果

独自のツールでは、testの代わりにrunを使います。何も書かずに、期待ごとにひとつのFix::Resultを、行の順に結果として返します。

require "fix"

Fix :Tax do
  on :*, 0.2 do
    it MUST eq 20
  end
end

results = Fix[:Tax].run { 100 }
results.map(&:outcome)  # => [:failure]
result = results.first
result.passed?          # => false
result.chain            # => ".*(0.2)"
result.summary          # => "expected 20.0 to eq 20"

結果は、location、outcome、そしてその背後にあるSpectusの結果ももっています。fixのREADMEに一覧があります。
