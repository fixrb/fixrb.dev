RSpecやminitestと並べて使う

プロジェクトがすでに持っているテストスイートを残したまま、Fixの仕様を加える。

RSpecやminitestでテストを書いているプロジェクトは、Fixを使うためにそれらを置き換える必要はありません。仕様は、いまのテストスイートにそのまま加えます。まずはテストスイートのテストから確かめ、仕様が増えてきたら、テストスイートが実行する専用のディレクトリに置きます。テストスイートは何も変わりません。Fixを外すときも、Gemfileの1行といくつかのファイルを消すだけです。

テストの中の仕様

下のプロジェクトは、libにクラスをひとつ持っています。

class Duck
  def walk = "Klop klop!"
  def swim = "Splash!"
  def speak = "Quaaack!"
end

その仕様は、Fixだけをrequireする専用のファイルに書いたドキュメントです。specはRSpecのディレクトリであることが多いので、ここではfix/specs/duck.rbに置きます。

require "fix"

Fix :Duck do
  on :walk do
    it MUST eq "Klop klop!"
  end

  on :swim do
    it SHOULD eq "Swoosh..."
  end

  on :speak do
    it MAY eq "Quaaack!"
  end
end

minitest-fixを使えば、minitestのテストはアサーションひとつでそれを確かめます。

require "minitest/autorun"
require "minitest/fix"
require_relative "../fix/specs/duck"
require_relative "../lib/duck"

class DuckTest < Minitest::Test
  include Minitest::Fix

  def test_duck_meets_its_specification
    assert_fix :Duck, Duck.new
  end
end

rspec-fixを使えば、RSpecのexampleはマッチャーひとつでそれを確かめます。

require "rspec/autorun"
require "rspec/fix"
require_relative "../fix/specs/duck"
require_relative "../lib/duck"

RSpec.configure { |config| config.include RSpec::Fix }

RSpec.describe Duck do
  it { is_expected.to fix(:Duck) }
end

それぞれの最初の行、minitest/autorunとrspec/autorunは、rubyでファイルをそのまま実行できるようにするものです。テストスイートでは、ヘルパーに書くか、コマンドに任せます。どちらも成功します。アヒルは要求どおりに歩くからです。推奨どおりには泳ぎませんが、どちらもそれを伝えません。満たされないSHOULDはWarningで、成功として扱われ、アサーションやマッチャーにはそれを書く行がないからです。MUSTが満たされないとき、失敗のメッセージはFixの行でできています。満たされなかった期待ごとに1行で、それぞれが仕様の行を指します。このように確かめる仕様はwithなしで書きます。テストは値を一度だけ与え、コンテキストがそれを作り直すことはできないからです。

ひとつのコマンド

Fixのテストは、Warningも含めてすべての行を出力します。それはfixのファイルで、同じドキュメントをrequireし、テストの結果をステータスにして終わります。

require_relative "specs/duck"
require_relative "../lib/duck"

exit(Fix[:Duck].test { Duck.new })

fix
fix/specs/duck.rb:5: Success: expected "Klop klop!" to eq "Klop klop!"
fix/specs/duck.rb:9: Warning: expected "Splash!" to eq "Swoosh..."
fix/specs/duck.rb:13: Success: expected "Quaaack!" to eq "Quaaack!"
1 file met

このコマンドは仕様を実行するにあります。こうするとプロジェクトにはコマンドがふたつになり、Rakefileがそれらを順に実行します（ほかのテストと並べる）。あるいは、テストスイート自身がfixのファイルを、それぞれ自分のテストのひとつとして実行すれば、コマンドもレポートもまたひとつになります。

require "minitest/autorun"
require "rbconfig"

# Every file of fix/ is a test of this suite: passed when it exits with 0,
# and what it wrote is the message when it does not.
class FixTest < Minitest::Test
  Dir.glob(File.join(__dir__, "..", "fix", "**", "*_fix.rb")).each do |file|
    define_method("test_#{File.basename(file, ".rb")}") do
      output, = capture_subprocess_io { system(RbConfig.ruby, file) }
      assert_predicate $?, :success?, output
    end
  end
end

各ファイルは、fixが実行するときと同じように専用のプロセスで実行され、ステータスが0でないときは、ファイルが出力したものがテストのメッセージになります。

テストのプロセス

Fixのテストでは、testのブロックがサブジェクトを作り、各コンテキストは子プロセスで実行されます。ここでは、テストスイートのテストが、自分のプロセスの中で値を作っています。そこにはテストのトランザクションも、モックも、カバレッジツールもあります。assert_fixとfixは、仕様のメソッドをその場で、その値に送ります。値を変えるメソッドは、続くコンテキストとテストの残りの部分にとっても、その値を変えます。

どちらもfork: trueを受け取ります（assert_fix :Duck, duck, fork: true、fix(:Duck, fork: true)）。このときは、Fixと同じように各コンテキストを子プロセスで実行します。メソッドは値のコピーに送られ、テストが持っている値はそのまま残ります。これは、状態がすべてプロセスの中にある値のためのものです。モックやテストダブルには子プロセスが受け取った呼び出しが見えず、カバレッジツールは子プロセスで実行されたものを数えません。exit!を呼ぶメソッドは、テストスイートではなく自分の子プロセスを終わらせ、テストはAw::ChildErrorを発生させます。

Railsアプリケーションで

Fixと同じように、Gemfileのtestグループにrequire: falseをつけてgemを加え、ActiveSupport::TestCaseにMinitest::Fixをincludeするか、RSpecのヘルパーでexampleにRSpec::Fixを与えてください。Railsのテストはトランザクションの中で実行され、終わるとロールバックされます。そのトランザクションは、テストのプロセスのコネクションのものです。子プロセスは自分のコネクションを受け取ります。Rails 8.1とSQLiteのアプリケーションで、仕様が出会ったのは次のとおりです。

仕様が行うことテストのプロセスの中でfork: trueのとき
テストが作った行を読む見つかる見つからないか、0件と数える。エラーのない、誤った値
テストが書き込んだあとに書き込むトランザクションの中で書き込むロックを待ち（ここでは5秒）、失敗する
テストが書き込む前に書き込むトランザクションの中で書き込むコミットされる。行はロールバックされず、テストのあとも残る

したがって、データベースを読み書きする値は、テストのプロセスの中で確かめます。指定しないかぎり、ふたつのgemはそうします。もうひとつの方法はRailsアプリケーションで使うにあります。fixに置くFixのテストで、サブジェクトごとに最初にデータベースを空にします。

そこから先

プロジェクトは、テストの中のひとつの仕様から始めます。ふたつめは多くの場合、いくつかのクラスが共有する契約、つまりインターフェースとその実装です。パターンでは、それを一度だけ書き、それぞれの実装をテストします。そこから先、チームはテストスイートをそのまま残し、新しいものをfixに仕様として書いていけます。各イディオムが何になるかは、RSpecからの移行とminitestからの移行にあります。

Fixを外すには、Gemfileからgemを、仕様を確かめるテストを、そしてfixディレクトリを消します。テストスイートは元のままです。
