RSpecからの移行

同じ考え方を別の名前で。そして、意図して省いたいくつかのもの。

  1. 構造
  2. マッチャー
  3. pendingの代わりに3つのレベル
  4. 意図して省いたもの

RSpecもFixも、入れ子のコンテキストと期待で振る舞いを記述します。根本で異なる点は2つです。Fixの仕様はクラスを名指ししません。サブジェクトは最後の行のテストから来るので、同じ仕様で別のサブジェクトもテストできます。そして仕様は文書で、ファイルの読み込み時に一度だけ読まれます。期待の前や後に実行されるコードはもちません。

subjectをもち、あるコンテキストではbeforeでインクリメントし、別のコンテキストではletを上書きする、カウンターのRSpecのspecは、次のようになります。

require "fix"

class Counter
  attr_reader :count

  def initialize(start) = @count = start
  def increment = tap { @count += 1 }
end

Fix :Counter do
  let(:start) { 0 }

  on :count do
    it MUST eq 0
  end

  on :increment do
    on :count do
      it MUST eq 1
    end
  end

  with start: 5 do
    on :count do
      it MUST eq 5
    end
  end
end

exit(Fix[:Counter].test { Counter.new(start) })

ruby counter_fix.rb
counter_fix.rb:14: Success: expected 0 to eq 0
counter_fix.rb:19: Success: expected 1 to eq 1
counter_fix.rb:25: Success: expected 5 to eq 5

beforeは連鎖のメソッドになりました。incrementがカウンターを返し、そこにcountが送られます。連鎖を超える準備が必要なメソッドは、letを使ってサブジェクトブロックの中で準備します。

pendingの代わりに3つのレベル

RSpecはexampleをスキップしたり、失敗しても実行全体が失敗しないようpendingをつけたりします。Fixはそれを仕様そのものの中で述べます。推奨されることにはSHOULDを使い、満たされなければWarningになります。任意のことにはMAYを使い、メソッドがなければInfoになります。どちらも成功として扱われ、どちらも行に書かれるので、何も隠れません。5つの判定は仕様を書くにあります。

意図して省いたもの

  • フック（before、after、around）。サブジェクトに必要なものはサブジェクトブロックが期待ごとに作り、各コンテキストは専用のプロセスで実行されるので、メモリの中に片付けるものはありません。
  • テストダブルとモック（double、allow(…).to receive）。サブジェクトには本物のオブジェクトか、サービスの代わりになるファイル内の小さなオブジェクトを、letを通して与えてください。仕様が述べるのはサブジェクトが何をするかであって、どんなメッセージを送るかではありません。
  • exampleの間の共有状態（before(:all)、インスタンス変数）。letはひとつのサブジェクトとともに存在し、コンテキストは別のコンテキストに手を出せません。値を共有するのはwithだけで、それもそのコンテキストの中に限られます。
  • タグとフィルター（focus）。fixはファイルとディレクトリを受け取り、ファイルは単独で実行できるプログラムです。
  • aggregate_failures。満たされてもされなくても、すべての期待に行が書かれます。

両方をひとつのプロジェクトに、それぞれのディレクトリで共存させることもできます。その方法はプロジェクトで使うにあります。
