仕様を組み合わせる

仕様はマッチャーです。ここでも、ほかのテストフレームワークでも、仕様は別の仕様を求めることができます。

  1. 仕様の中で：fix
  2. Rubyで：match?
  3. ほかのフレームワークで：matchi-fix

仕様はサブジェクトが何をするかを述べます。そのなかには、一度述べれば多くのサブジェクトに当てはまるものがあります。空のコレクションがすること、名前の形、どのプラグインも答えることなどです。それを独立した仕様として書けば、ほかの仕様がそれを求めることができます。

仕様の中で：fix

マッチャーfix(:Name)は、実際の値がその名前の仕様を満たすときに満たされます。ここでは、スタックは新しいときには空でなければならず、何かをpushしたあとは空であってはなりません。

require "fix"

Fix :Empty do
  on :empty? do
    it MUST be_true
  end

  on :size do
    it MUST eq 0
  end
end

Fix :Stack do
  it MUST fix(:Empty)

  on :push, 1 do
    it MUST_NOT fix(:Empty)

    on :last do
      it MUST eq 1
    end
  end
end

exit(Fix[:Stack].test { [] })

ruby stack_fix.rb
stack_fix.rb:14: Success: expected [] to fix Empty
stack_fix.rb:17: Success: expected [1] not to fix Empty
stack_fix.rb:20: Success: expected 1 to eq 1
  • 仕様はファイルの読み込み時に探されるので、その前に書くか、それを書いたファイルをrequireしてください。知らない名前はその時点でKeyError（no specification named :Nope）になります。
  • 値はサブジェクトとしてテストされます。Emptyの各コンテキストが、それぞれ専用の子プロセスでその値にメソッドを送り、その行は書かれません。fixは、WarningやInfoも含めてすべてが成功として扱われたときに満たされます。
  • 満たされなかったfixは、仕様が満たされないことを伝えるだけで、どの期待が失敗したかは伝えません。それを見るには、同じ値でその仕様を単独でテストしてください。
  • fix { … }は、一度だけ使う要求のために、名前をつけずにその場で仕様を書きます。
  • fixのための仕様はwithなしで書きます。受け取る値はすでにできあがっているので、letで変えることはできません。

Rubyで：match?

仕様は、どのマッチャーとも同じくmatch?に答えます。ブロックが値を与え、答えはその値が仕様を満たすかどうかを示します。ここではEmptyが、配列にもハッシュにも文字列にも同じように当てはまります。

require "fix"

Fix :Empty do
  on :empty? do
    it MUST be_true
  end

  on :size do
    it MUST eq 0
  end
end

Fix[:Empty].match? { [] }    # => true
Fix[:Empty].match? { {} }    # => true
Fix[:Empty].match? { "" }    # => true
Fix[:Empty].match? { [nil] } # => false

match?は何も書きません。行を書くにはtestを、結果を得るにはrunを使います。

ほかのフレームワークで：matchi-fix

Matchiのマッチャーはどのテストフレームワークでも使え、matchi-fixはFixの仕様をそのひとつにします。Matchi::Fix.new(:Name)、その場で書く仕様ならMatchi::Fix.new { … }です。gem install matchi-fixでインストールし、matchi/fixをrequireします。

require "fix"
require "matchi/fix"

Fix :Empty do
  on :empty? do
    it MUST be_true
  end
end

matcher = Matchi::Fix.new(:Empty)
matcher.to_s          # => "fix Empty"
matcher.match? { [] } # => true

Spectus.must(matcher).call { [nil] }.to_s # => "Failure: expected [nil] to fix Empty"

最後の行は、Fixの土台であるSpectusを使っています。minitestでは、assertがその答えを受け取ります（assert Matchi::Fix.new(:Empty).match? { [] }）。ほかのフレームワークでテストを書いているプロジェクトも、テストを移さずに、同じ仕様をそのテストの中で使えます。

Fixの仕様の中では、it MUST Matchi::Fix.new(:Empty)とit MUST fix(:Empty)は同じです。fixにはほかのgemは要りません。
