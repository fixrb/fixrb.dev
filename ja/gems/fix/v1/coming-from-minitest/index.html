minitestでは、テストはメソッドです。オブジェクトを作り、それに働きかけ、出てきたものをアサーションで確かめます。Fixはこれをふたつに分けます。仕様は、何が出てこなければならないかを述べるドキュメントで、クラスの名前を含まず、期待の前後に実行されるコードも持ちません。テストは最後の行でサブジェクトを与えるので、同じ仕様で別のサブジェクトもテストできます。このページはテストクラスとアサーションについて述べます。describeとitで書くminitest/specには、RSpecからの移行のほうが近いでしょう。

カウンターのテストクラスがあるとします。setupがあり、カウンターを増やすテストと、別の値からカウンターを作るテストがあります。

require "minitest/autorun"

class Counter
  attr_reader :count

  def initialize(start) = @count = start
  def increment = tap { @count += 1 }
end

class CounterTest < Minitest::Test
  def setup
    @counter = Counter.new(0)
  end

  def test_count
    assert_equal 0, @counter.count
  end

  def test_count_after_an_increment
    assert_equal 1, @counter.increment.count
  end

  def test_count_from_five
    assert_equal 5, Counter.new(5).count
  end
end

これは次のようになります。

require "fix"

class Counter
  attr_reader :count

  def initialize(start) = @count = start
  def increment = tap { @count += 1 }
end

Fix :Counter do
  let(:start) { 0 }

  on :count do
    it MUST eq 0
  end

  on :increment do
    on :count do
      it MUST eq 1
    end
  end

  with start: 5 do
    on :count do
      it MUST eq 5
    end
  end
end

exit(Fix[:Counter].test { Counter.new(start) })

ruby counter_fix.rb

counter_fix.rb:19: Success: expected 1 to eq 1
counter_fix.rb:25: Success: expected 5 to eq 5

setupはテストのブロックになり、カウンターに与えていた値はletになりました。withは、ひとつのコンテキストのためにそれを変えます。アサーションの前の呼び出しは、チェーンのメソッドになりました。incrementがカウンターを返し、それにcountが送られます。

skipの代わりに3つのレベル

minitestはskipでテストをスキップします。スキップしたテストは別に数えられ、そのアサーションは実行されません。Fixはそれを仕様そのものの中で述べます。推奨されることにはSHOULDを使い、満たされなければWarningになります。任意のことにはMAYを使い、メソッドがなければInfoになります。どちらも成功として扱われ、どちらも実行され、どちらも行に書かれるので、何も隠れません。5つの判定は仕様を書くにあります。

意図して省いたもの

  • setupとteardown。サブジェクトに必要なものはサブジェクトブロックが期待ごとに作り、各コンテキストは専用のプロセスで実行されるので、メモリの中に片付けるものはありません。
  • モックとスタブ（Minitest::Mock、stub）。サブジェクトには本物のオブジェクトか、サービスの代わりになるファイル内の小さなオブジェクトを、letを通して与えてください。仕様が述べるのはサブジェクトが何をするかであって、どんなメッセージを送るかではありません。
  • テスト間の共有状態（インスタンス変数、クラス変数）。letはひとつのサブジェクトとともにあり、コンテキストは別のコンテキストに届きません。値を共有するのはwithだけで、それも自分のコンテキストの中だけです。
  • テストのランダムな順序。minitestは、互いに依存するテストを見つけるためにテストをシャッフルします。Fixのコンテキストは書かれた順に、それぞれのプロセスで実行されるので、順序が結果を変えることはありません。fix --randomはファイルをシャッフルします。ファイルは、プロセスの外にあるものを共有するからです。
  • 独自のメッセージ（アサーションの最後の引数）。すべての期待に、期待したものと出てきたものを示す行が書かれます。

どちらも同じプロジェクトで使えますし、minitestのテストからFixの仕様を確かめることもできます。その方法はRSpecやminitestと並べて使うにあります。
