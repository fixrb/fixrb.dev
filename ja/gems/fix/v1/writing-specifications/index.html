Fix 1ガイド

仕様を書く

4つの語on、let、with、itと、3つの要求レベル。

  1. メソッド：on
  2. パラメーター：letとwith
  3. 期待：it
  4. コンテキストごとにひとつのプロセス

Fixのブロックは文書です。ファイルの読み込み時に一度だけ読まれ、サブジェクトが存在する前に仕様を組み立てます。セットアップも後片付けも状態もありません。要求のないitや、ひとつのコンテキストで2回宣言されたletなど、誤りがあればその時点で、どのテストよりも前に例外になります。

メソッド：on

onは、サブジェクトにメソッドを引数とともに送るコンテキストを開きます。その中の期待は、返ってきた値を判定します。ほかのonの中に置くと、その値にメソッドを送り、以下同様に続きます。どのonにも入っていないitは、サブジェクトそのものを判定します。

require "fix"

Fix :Phrase do
  it MUST be_an_instance_of String

  on :upcase do
    it MUST eq "HELLO WORLD"

    on :length do
      it MUST eq 11
    end
  end

  on :split, " " do
    it MUST eq %w[hello world]
  end

  on :start_with?, "hello" do
    it MUST be_true
  end
end

exit(Fix[:Phrase].test { "hello world" })

ruby phrase_fix.rb
phrase_fix.rb:4: Success: expected "hello world" to be an instance of String
phrase_fix.rb:7: Success: expected "HELLO WORLD" to eq "HELLO WORLD"
phrase_fix.rb:10: Success: expected 11 to eq 11
phrase_fix.rb:15: Success: expected ["hello", "world"] to eq ["hello", "world"]
phrase_fix.rb:19: Success: expected true to be true

問い合わせもメソッドです。on :start_with?, "hello"がそれを尋ね、be_trueは答えがtrueであることを求めます。例外を発生させたメソッドは、そこで連鎖を終わらせ、その期待はErrorになります。ただし、そのためにあるマッチャーraise_exceptionを使う期待は別です。onのブロックはコンテキストなので、メソッドはブロックなしで送られます。

パラメーター：letとwith

letはサブジェクトのパラメーターで、名前と、その値を与えるブロックからなります。testのブロックがそれを呼んでサブジェクトを作ります。withは、パラメーターが別の値をとるコンテキストを開きます。

require "fix"

class Price
  def initialize(amount, rate: 0)
    @amount = amount
    @rate = rate
  end

  def total = @amount - (@amount * @rate / 100)
end

Fix :Price do
  let(:amount) { 100 }
  let(:rate) { 0 }

  on :total do
    it MUST eq 100

    with rate: 20 do
      it MUST eq 80
    end
  end

  with amount: 50, rate: 10 do
    on :total do
      it MUST eq 45
    end
  end
end

exit(Fix[:Price].test { Price.new(amount, rate:) })

ruby price_fix.rb
price_fix.rb:17: Success: expected 100 to eq 100
price_fix.rb:20: Success: expected 80 to eq 80
price_fix.rb:26: Success: expected 45 to eq 45

コンテキストは、それを囲むコンテキストのパラメーターとメソッドを受け継ぎます。on :totalの中で、with rate: 20は20%の価格を作り、それにtotalを送ります。withはonの前に置くことも、中に置くこともできます。

  • letはサブジェクトブロックとほかのletからは見えますが、期待からは見えません。期待はサブジェクトが存在する前に書かれるからです。期待の中でletの名前を使うと、読み込み時にNameErrorになります。
  • letの値は最初に呼ばれたときに計算され、その期待の間は保持されます。期待はそれぞれサブジェクトを作り直します。let(:items) { [] }はそれぞれに専用の配列を与えますが、with items: []はそのコンテキストの期待に同じ配列を与えます。
  • letには、formatのように公開・非公開を問わずどのオブジェクトにもあるメソッドの名前や、eqのようなFixの語の名前はつけられません。let(:format)は読み込み時にArgumentError（format is already a method of Kernel）になるので、何かが黙って再定義されることはありません。

期待：it

itは要求をとります。it MUST eq 100のように、レベルのあとにマッチャーを書きます。レベルはRFC 2119の言葉で、MUST、SHOULD、MAY、否定にはMUST_NOTとSHOULD_NOTがあります。RFC 2119には否定のMAYはありません。マッチャーには専用のページがあります。

require "fix"

Player = Data.define(:name, :score)

Fix :Player do
  on :name do
    it MUST eq "Ada"
  end

  on :score do
    it MUST_NOT be_nil
    it SHOULD eq 100
  end

  on :avatar do
    it MAY match(/\.png\z/)
  end
end

exit(Fix[:Player].test { Player.new(name: "Ada", score: 90) })

ruby player_fix.rb
player_fix.rb:7: Success: expected "Ada" to eq "Ada"
player_fix.rb:11: Success: expected 90 not to be nil
player_fix.rb:12: Warning: expected 90 to eq 100
player_fix.rb:16: Info: NoMethodError: undefined method 'avatar' for an instance of Player

2つの問いがレベルを分けます。メソッドは存在しなければならないか。MUSTとSHOULDは「はい」、MAYは「いいえ」です。書かれたとおりに動かなければならないか。MUSTとMAYは「はい」、SHOULDは推奨するだけです。そこから5つの判定が生まれます。

レベルそのとおりに動くそのとおりに動かないメソッドがないほかの例外
MUSTSuccessFailureErrorError
SHOULDSuccessWarningErrorError
MAYSuccessFailureInfoError

Success、Warning、Infoは成功として扱われます。上の例のプレイヤーは仕様を満たし、プロセスの終了ステータスは0です。FailureとErrorはそうではありません。否定は最初の2列を入れ替えます。MUST_NOT be_nilは、スコアがnilでないときにSuccessになります。

Errorの下には、そのバックトレースのうちFixとそのgemに属さないフレームが、空白2つで字下げされて続きます。例外を発生させたコードの行がそこに示されるわけです。マッチャーのページのraise_exceptionの項に例があります。

コンテキストごとにひとつのプロセス

期待をもつコンテキストはそれぞれ、テストするプロセスの子プロセスで実行されます。ひとつのコンテキストの期待は同じ子プロセスで実行され、コンテキストは順に、外側のものが内側のものより先に実行されます。サブジェクトがプロセスの中で変えたもの、つまりグローバル変数、定数、カレントディレクトリ、ENVはそのコンテキストの中にとどまり、コンテキストの順序が結果を変えることはありません。プロセスの外で変えたもの、つまりファイルやデータベースはとどまりません。これについてはプロジェクトで使うで改めて扱います。
