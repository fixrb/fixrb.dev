fix

Rubyのテストフレームワーク。RFC 2119の言葉で書いた仕様で、サブジェクトをテストする。

  • ガイドを始める
  • RSpecからの移行

仕様は、サブジェクトが何をMUST（しなければならない）、SHOULD（すべきである）、MAY（してもよい）かを、RFC 2119の言葉で述べます。何を必須とし、何を推奨し、何を任意とするかです。仕様はクラスを名指ししないので、ひとつの仕様で複数の実装も、依存しているライブラリも、リリースごとの同じオブジェクトもテストできます。各コンテキストは子プロセスで実行され、すべての期待に結果が出ます。

インストール

Gemfileにgem "fix"を加えるか、gem install fixを実行してください。

ひとつのファイルで

ファイルは仕様を書き、それに対してサブジェクトをテストします。ここではアヒルと、アヒルとして作られたわけではないロボットです。Fix :Duck do … endは仕様を組み立て、その名前で登録します。Fix[:Duck]がそれを再び見つけます。testは期待ごとにブロックで新しいサブジェクトを作り、期待を囲むonのメソッドをサブジェクトに送り、出てきたものを判定して、期待ごとに1行を書き、すべてが成功したかどうかを返します。exitはそれをプロセスの終了ステータスにします。

require "fix"

# What a duck does, whatever it is made of.
Fix :Duck do
  on :walk do
    it MUST eq "Klop klop!"
  end

  on :swim do
    it SHOULD eq "Swoosh..."
  end

  on :speak do
    it MAY eq "Quaaaaaack!"
  end
end

class Duck
  def walk = "Klop klop!"
  def swim = "Swoosh..."
  def speak = "Quaaaaaack!"
end

class Robot
  def walk = "Klop klop!"
  def swim = "Glug glug..."
end

duck = Fix[:Duck].test { Duck.new }
robot = Fix[:Duck].test { Robot.new }
exit(duck && robot)

ruby duck.rb
duck.rb:6: Success: expected "Klop klop!" to eq "Klop klop!"
duck.rb:10: Success: expected "Swoosh..." to eq "Swoosh..."
duck.rb:14: Success: expected "Quaaaaaack!" to eq "Quaaaaaack!"
duck.rb:6: Success: expected "Klop klop!" to eq "Klop klop!"
duck.rb:10: Warning: expected "Glug glug..." to eq "Swoosh..."
duck.rb:14: Info: NoMethodError: undefined method 'speak' for an instance of Robot

最初の3行がアヒルの、最後の3行がロボットの行です。ロボットは自分なりのやり方で泳ぎます。満たされないSHOULDはWarningです。ロボットにはspeakがありません。MAYのもとでは、サブジェクトにないメソッドはInfoです。どちらも成功として扱われるのでファイルは0で終了し、どちらも書かれるので足りない点もわかります。もしロボットがアヒルのように歩かなかったら、それはMUSTなので行はFailureとなり、終了ステータスは1になったでしょう。仕様はどちらのクラスも名指ししません。専用のファイルに置いて、walkをもつどんなものに対してもテストできます。サブジェクトがひとつなら、最後の数行は1行になります（exit(Fix[:Duck].test { Duck.new })）。括弧は残してください。exit Fix[:Duck].test do … endでは、ブロックがexitに渡ってしまいます。

Fixの役割

Rubyは以前から、いくつかの仕様を、それを実装するものから切り離してきました。Rack::LintはどんなアプリケーションもどんなサーバーもRackの仕様に照らして確かめ、ruby/specは言語を実装するすべてのRubyのために言語を記述し、複数のアダプターをもつライブラリは各アダプターが通るべきexampleを書きます。Fixは、そうした仕様を独立した文書にします。一度だけ書き、どのテストよりも前に読まれ、3つのレベルをもち、どんなオブジェクトに対してもテストでき、パターンが示すように、実装する人のためにgemに同梱できる文書です。

Fixはプロジェクトのフレームワークを置き換えるものではありません。フィクスチャーやテストダブル、アプリケーションフレームワークが必要なテストスイートは、そのためにRSpecやminitestを使い続けます。Fixが担うのは、部品どうしが合意する振る舞い、つまりインターフェースや依存ライブラリの契約で、それをspecやtestの隣のfixディレクトリに置き、専用のコマンドで実行します。そしてmatchi-fixが、そうした仕様をマッチャーとしてそのフレームワークに持ち込みます。RSpecからの移行はRSpecの各イディオムが何になるかを示し、よくある質問は両者を併用するときの疑問に答えます。表では、FixをRSpecやminitestと項目ごとに比べています。

Fixが省いたもの

モックも、beforeとafterも、共有exampleも、ランダムな順序もありません。仕様がもつのは期待だけで、テストに必要な準備は、letのあるサブジェクトブロックで行います。同じ仕様で、クラスも、モジュールも、インスタンスも、ライブラリもテストでき、毎回同じ結果が出ます。Fixにはforkが必要です。LinuxとmacOSでテストされており、WindowsやJRubyでは動きません。

仕様の使いみち

ひとつの仕様、いくつものサブジェクト

仕様は一度だけ書き、何に対してもテストできます。サブジェクトを選ぶのは仕様ではなくtestのブロックです。ここでは、スタックをその振る舞いで記述し、Arrayと連結リストに対してテストします。入れ子のonはメソッドの連鎖になり、それぞれがひとつ上の戻り値に送られます。そのため、popが続くにはpushがスタックを返す必要があります。

require "fix"

Fix :Stack do
  on :empty? do
    it MUST be_true
  end

  on :push, 1 do
    on :push, 2 do
      on :pop do
        it MUST eq 2
      end

      on :size do
        it MUST eq 2
      end
    end
  end

  on :pop do
    it MUST be_nil
  end
end

class LinkedStack
  Node = Data.define(:value, :below)

  def initialize = @top = nil
  def empty? = @top.nil?
  def size = each_node.count
  def push(value) = tap { @top = Node.new(value, @top) }

  def pop
    value = @top&.value
    @top = @top&.below
    value
  end

  private

  def each_node
    return to_enum(:each_node) unless block_given?

    node = @top
    while node
      yield node
      node = node.below
    end
  end
end

Fix[:Stack].test { [] }               # => true
Fix[:Stack].test { LinkedStack.new } # => true

3つのレベルの契約

RFC 2119のレベルは、アダプターがしなければならないこと、したほうがよいこと、しなくてもよいことを述べます。満たされないMUSTはビルドを失敗させます。満たされないSHOULDはWarning、サブジェクトにないメソッドへのMAYはInfoで、どちらも成功として扱われ、どちらも書かれるので、誰も止めずに足りない点がわかります。letはサブジェクトのパラメーターを宣言し、withはそれが別の値をとるコンテキストを開きます。testのブロックはそれを読んでサブジェクトを作ります。

require "fix"

# What the application needs from a cache: a contract, in three levels.
Fix :Cache do
  let(:entries) { {} }

  on :read, :answer do
    it MUST be_nil
  end

  with entries: { answer: 42 } do
    on :read, :answer do
      it MUST eq 42
    end
  end

  on :write, :answer, 42 do
    it SHOULD be_true
  end

  on :clear do
    it MAY be_nil
  end
end

class MemoryCache
  def initialize = @store = {}
  def read(key) = @store[key]
  def write(key, value) = @store[key] = value
end

exit(Fix[:Cache].test { entries.each_with_object(MemoryCache.new) { |(key, value), cache| cache.write(key, value) } })

ruby cache.rb
cache.rb:8: Success: expected nil to be nil
cache.rb:13: Success: expected 42 to eq 42
cache.rb:18: Warning: expected 42 to be true
cache.rb:22: Info: NoMethodError: undefined method 'clear' for an instance of MemoryCache

依存ライブラリに期待すること

サブジェクトは自分のものである必要はありません。仕様には、アプリケーションがライブラリに頼っていることを書いておき、そのライブラリをアップグレードするたびに実行できます。ここでは標準のJSONモジュールです。メソッドが発生させた例外は、例外として判定されます。raise_exceptionはそれを期待し、ほかのマッチャーはErrorを報告します。

require "fix"
require "json"

# What the application expects of a library it depends on, tested at each
# upgrade of that library.
Fix :JSON do
  on :generate, [1, 2] do
    it MUST eq "[1,2]"
  end

  on :parse, "[1,2]" do
    it MUST eq [1, 2]
  end

  on :parse, "nope" do
    it MUST raise_exception JSON::ParserError
  end

  on :pretty_generate, [1] do
    it SHOULD eq "[\n  1\n]"
  end
end

exit(Fix[:JSON].test { JSON })

ruby json.rb
json.rb:8: Success: expected "[1,2]" to eq "[1,2]"
json.rb:12: Success: expected [1, 2] to eq [1, 2]
json.rb:16: Success: expected #<JSON::ParserError: unexpected token 'nope' at line 1 column 1> to raise exception JSON::ParserError
json.rb:20: Success: expected "[\n  1\n]" to eq "[\n  1\n]"

組み合わせられる仕様

仕様はマッチャーです。fix(:Name)は登録済みの仕様を、fix { … }はその場で書いた仕様を求め、ほかのマッチャーと同じようにレベルがかかります。満たされなかったfixは、仕様が満たされないことを伝えるだけで、どの期待が失敗したかは伝えません。詳しく見るには、その仕様を単独でテストしてください。

require "fix"

Fix :Positive do
  on :positive? do
    it MUST be_true
  end
end

Fix :Score do
  it MUST be_a_kind_of Numeric
  it MUST fix(:Positive)
  it MUST_NOT fix { on(:nan?) { it MUST be_true } }
end

exit(Fix[:Score].test { 7.5 })

ruby compose.rb
compose.rb:10: Success: expected 7.5 to be a kind of Numeric
compose.rb:11: Success: expected 7.5 to fix Positive
compose.rb:12: Success: expected 7.5 not to fix an anonymous specification

漏れない状態

期待をもつコンテキストはそれぞれ、awを使って、テストするプロセスからforkした子プロセスで実行されます。グローバル変数、定数、ENV、カレントディレクトリに書き込むサブジェクトも、それを行うのは自分の子プロセスの中だけです。どのコンテキストもファイルを読み込んだときの状態から始まり、コンテキストの順序が結果を変えることはありません。

require "fix"

# A subject with a global state: every context starts from the state the
# file was loaded with, since each one runs in a child process.
module Registry
  NAMES = []

  def self.add(name) = tap { NAMES << name }
  def self.names = NAMES
end

Fix :Registry do
  on :add, "Alice" do
    on :names do
      it MUST eq ["Alice"]
    end
  end

  on :add, "Bob" do
    on :names do
      it MUST eq ["Bob"]
    end
  end

  on :names do
    it MUST eq []
  end
end

exit(Fix[:Registry].test { Registry })

ruby registry.rb
registry.rb:15: Success: expected ["Alice"] to eq ["Alice"]
registry.rb:21: Success: expected ["Bob"] to eq ["Bob"]
registry.rb:26: Success: expected [] to eq []

言語

Fixのブロックは文書で、ファイルの読み込み時に一度だけ読まれ、4つの語をもちます。on :name, *argumentsはサブジェクトにメソッドを送り、その中の期待が戻り値を判定します。let(:name) { … }はサブジェクトのパラメーターで、サブジェクトブロックが最初に呼んだときに、期待ごとに一度だけ計算されます。with name: valueは、それがその値をとるコンテキストを開きます。itは要求をとります。レベル（MUST、MUST_NOT、SHOULD、SHOULD_NOT、MAY）のあとにマッチャーを書きます。

require "fix"

Fix :Greeting do
  let(:name) { "Bob" }

  it MUST eq "Hello, Bob!"
  it MUST_NOT be_nil

  on :size do
    it MUST eq 11
  end

  with name: "Alice" do
    it MUST eq "Hello, Alice!"
  end
end

exit(Fix[:Greeting].test { "Hello, #{name}!" })

ruby greeting.rb
greeting.rb:6: Success: expected "Hello, Bob!" to eq "Hello, Bob!"
greeting.rb:7: Success: expected "Hello, Bob!" not to be nil
greeting.rb:10: Success: expected 11 to eq 11
greeting.rb:14: Success: expected "Hello, Alice!" to eq "Hello, Alice!"

マッチャーはmatchiのものを語として使います。eq、be、be_true、be_false、be_nil、be_within(delta).of、match、be_an_instance_of、be_a_kind_of、raise_exception、change、satisfy、そしてfixです。match?とto_sをもつオブジェクトも、どれもマッチャーになります。述語のためのヘルパーはありません。問いを立てるのはon(:empty?) { it MUST be_true }です。

letはサブジェクトブロックとほかのletからだけ見えます。期待の中で名前を使うと、読み込み時にNameErrorが対処法とともに発生します。letの名前には、サブジェクトを作るオブジェクトのメソッドの名前も、言語の語もつけられないので、何かが黙って再定義されることはありません。文書の誤りはすべて、ファイルの読み込み時に、どのテストよりも前に例外になります。ブロックをもつ、あるいは要求のないit、2回名づけたletや仕様、match?のないマッチャーなどです。例外を発生させたブロックは何も登録しません。

判定

2つの問いがレベルを分けます。メソッドは存在するか。MUSTとSHOULDはそれを求め、MAYは求めません。仕様どおりに動くか。MUSTとMAYはそれを求め、SHOULDは推奨します。そこから5つの判定が生まれ、そのうちSuccess、Warning、Infoは成功として扱われます。

レベル照合が真照合が偽メソッドがないほかの例外
MUSTsuccessfailureerrorerror
SHOULDsuccesswarningerrorerror
MAYsuccessfailureinfoerror

否定は最初の2列を入れ替えます。メソッドがないとは、そのコンテキストのonが名指ししたメソッドについて、送られたオブジェクトがNoMethodErrorを発生させた場合です。Errorの下に、testはバックトレースのうちFixとそのgemに属さないフレームを書くので、サブジェクトの行がそこに示されます。

require "fix"

class Account
  def initialize(balance)
    @balance = balance
  end

  attr_reader :balance

  def withdraw(amount)
    raise ArgumentError, "insufficient funds" if amount > balance

    @balance -= amount
  end
end

Fix :Account do
  on :balance do
    it MUST eq 100
    it MUST eq 200
    it SHOULD eq 200
  end

  on :currency do
    it MAY eq "EUR"
  end

  on :withdraw, 500 do
    it MUST eq(-400)
  end
end

Fix[:Account].test { Account.new(100) } # => false

結果とランナー

testは期待ごとに1行、LOCATION: OUTCOME: SUMMARYを書きます。サマリーはspectusのもので、ほかには何も書きません。記号も、色も、件数もありません。ファイルはrubyで実行し、仕様が満たされれば終了ステータスは0です。継続的インテグレーションにもRakefileにもランナーにも、必要なのはそれだけです。そして行の文法は、ランナーが読んで集計したり色をつけたりするためのものです。fix-commandはそうしたランナーで、fixコマンドは各ファイルを専用のプロセスで実行し、満たされたファイルの数を伝えます。runは同じ結果をデータとしてコンテキストの順に返し、match?はマッチャーと同じように値をテストします。

require "fix"

Fix :Size do
  it MUST be_an_instance_of String

  on :size do
    it MUST eq 3
  end
end

results = Fix[:Size].run { "abcd" }
results.map(&:outcome) # => [:success, :failure]
results.map(&:passed?) # => [true, false]

result = results.last
result.location # => "examples/fix/results.rb:7"
result.chain    # => ".size"
result.summary  # => "expected 4 to eq 3"
result.to_s     # => "examples/fix/results.rb:7: Failure: expected 4 to eq 3"
result.result.class # => Spectus::Result

Fix[:Size].match? { "abc" } # => true

プロセス

コンテキストは順に、それぞれの子プロセスで実行され、親プロセスは子プロセスが返したコンテキストの結果を書きます。サブジェクトが発生させた例外は、exitも含めて、その期待だけのErrorになります。子プロセスの周りで何かをrescueすることはありません。Interruptは実行を止め、異常終了した子プロセスもAw::ChildErrorで実行を止めます。Fixは、期待から得たものでない結果を書くことは決してありません。test(fork: false)は、デバッガーのために、コンテキストをプロセス自身の中で実行します。コンテキストのコストはforkひとつ、数ミリ秒です。

拡張

fix-itsはitsという語を加え、メソッドとその期待を1行にします。matchi-fixは、matchiのマッチャーを受け付けるどのフレームワークにも、Fixの仕様を持ち込みます。FixのブロックはFix::Dslのインスタンスの上で実行され、gemはそこに独自の語を加えられます。
