brutal

コードの振る舞いから、素のRubyのテストファイルを書き出す。

YAMLで書くマニフェストは、サブジェクト、組み合わせるコンテキスト、観測する実際の値を与えます。Brutalはあらゆる組み合わせをひとつの子プロセスで実行し、コードが返すものを記録して、それぞれの値をeql?で確かめるテストファイルを、フレームワークなしで書き出します。実行するのはruby test_greeter.rbです。テストファイルは、コードがすべきことではなく、コードが実際にすることの写しです。レビュー中のコードを読むのと同じように、信頼する前に読んでください。

インストール

Gemfileにgem "brutal", require: falseを加えるか、コマンドだけならgem install brutalを実行してください。Brutalはawを通じてforkした子プロセスでコードを実行するので、WindowsとJRubyには対応していません。

使い方

次のクラスがあるとします。

class Greeter
  def initialize(name)
    @name = name.capitalize
  end

  def salute
    "Hello #{@name}!"
  end
end

マニフェストはNAME_brutal.yamlという名前のファイルで、ここではクラスの隣のgreeter_brutal.yamlです。

header: |
  require_relative "greeter"

subject: |
  Greeter.new(%{name})

contexts:
  name:
    - '"Alice"'
    - '"world"'

actuals:
  - "%{subject}.salute"
  - "%{subject}.salute.length"

bundle exec brutal test/greeter_brutal.yaml

Brutalはマニフェストの隣にtest_greeter.rbを書き出します。

# Generated by brutal from greeter_brutal.yaml: edit the manifest, then run brutal again.

require_relative "greeter"

# ------------------------------------------------------------------------------

actual = begin
  Greeter.new("Alice")
end

::Kernel.raise "name = \"Alice\": actual.salute" unless ("Hello Alice!").eql?((
  actual.salute
))
::Kernel.raise "name = \"Alice\": actual.salute.length" unless (12).eql?((
  actual.salute.length
))

# ------------------------------------------------------------------------------

actual = begin
  Greeter.new("world")
end

::Kernel.raise "name = \"world\": actual.salute" unless ("Hello World!").eql?((
  actual.salute
))
::Kernel.raise "name = \"world\": actual.salute.length" unless (12).eql?((
  actual.salute.length
))

ruby test/test_greeter.rb

失敗した確認は、exampleと実際の値を示すRuntimeErrorを発生させ、ファイルの残りは実行されません。ファイルを読み込むテストランナーなら、どれでもこれを実行できます。

マニフェスト

7つのセクションがあり、contexts以外はRubyのコードをもちます。headerは最初のexampleの前に一度だけ、beforeは各exampleの前に実行されます。subjectは各exampleのコードで、コンテキストごとに%{name}をもちます。contextsは名前ごとのコード片のリスト、actualsは観測する式で、サブジェクトの値には%{subject}を使います。afterは各exampleのあとに、footerは最後のあとに一度だけ実行されます。必須なのはsubject、contexts、actualsだけです。exampleはコンテキストの組み合わせごとにひとつずつ、ファイルの順に作られます。

値はテキストとして読まれ、YAMLの型に変換されることはありません。1,2、yes、~は、Rubyのコード1,2、yes、~のままです。コード片はコードなので、文字列には上の'"Alice"'のように引用符が必要です。複数行の値はリテラルブロック（|）で書きます。各セクション、コード片を埋め込んだ各サブジェクト、各actualは、それだけで完結したコードでなければなりません。ある部分が開いたブロック、文字列、コメントを別の部分が閉じ、確認を飛ばしたり飲み込んだりできないようにするためです。アンカー、エイリアス、タグ、未知の・重複した・空のセクション、使われないコンテキスト、サブジェクトとactuals以外のプレースホルダーは拒否されます。

コードの実行のされ方

コードは、rubyがテストファイルを実行するのと同じように子プロセスで実行されます。トップレベルで、selfはmain、各セクションのローカル変数は後続のセクションから見え、__dir__はテストファイルのディレクトリです。カレントディレクトリから、あなたの権限で実行されるので、brutalは自分のマニフェストにだけ使ってください。コードがプロセスに対して行ったことは子プロセスの中にとどまり、外に対して、つまりファイルやほかのプロセスに対して行ったことは実際に起こります。

続いてbrutalは、テストファイルを書き出す前に、brutalを実行しているRubyで、新しいプロセスでそれを実行し、成功したときだけ書き出します。これで、brutalの子プロセスと実際の実行とで異なるもの、たとえば子プロセスがbrutalから受け継いだ定数、オブジェクトID、乱数を見つけられます。そのためコードは2回実行されます。変わっていないテストファイルも再び実行されます。--checkはコードを一度だけ実行し、何も書きません。

観測した値は、Rubyのバージョンやロケールにかかわらず同じになるRubyのリテラルとして書かれます。nil、true、false、Integer、有限のFloat、UTF-8・バイナリ・ASCII文字だけのString、Symbol、そしてそれらのArrayやHashで、クラスは厳密に一致するものに限ります。それ以外はexampleとactualを示して拒否され、inspectの文字列として書かれることは決してありません。代わりに、.to_s、.to_a、.to_h、.sizeのような射影を観測してください。確認は(expected).eql?((actual))で、matchiと同じく呼び出しを受けるのは期待値です。1と1.0は異なり、何とでも等しいと主張するオブジェクトは通りません。理由はテストにおける期待値と実際の値の根本的な違いにあります。

コマンド

brutal PATH...は、与えたNAME_brutal.yamlごとに、あるいは与えたディレクトリとそのサブディレクトリで見つけたものごとに、その隣にtest_NAME.rbを書き出します。隠しエントリーとディレクトリへのシンボリックリンクは除かれます。失敗したマニフェストはパスと理由とともに標準エラーに報告され、ほかのマニフェストはそのまま実行されます。終了ステータスは、すべてのマニフェストが成功すれば0、失敗したものがあるか、パスがマニフェストを指していなければ1、使い方の誤りなら2です。

テストファイルは、一時ファイルを書いて置き換える形で、全体が書かれるか、まったく書かれないかのどちらかです。置き換えるのはbrutalが書いたファイルだけで、その1行目にそう記されています。手で書いたテストファイルやbrutal 1が書いたテストファイルはエラーになります。brutal --check PATH...はすべてのテストファイルをメモリ上で生成し、置かれているものと比べます。CIで実行すれば、テストファイルがマニフェストからずれることはありません。

制限

  • brutalが書いたテストファイルは、コードをあるがままに記述します。コードが誤っていても、すべての確認は通ります。レビュー中のコードと同じように、読むためのファイルです。
  • brutalの2回の実行ではたまたま同じでも、あなたの実行では異なる値（現在の分、小さな乱数）は見つけられません。そうした値や、__FILE__と$0は観測しないでください。
  • 確認は::Kernel.raise … unless (expected).eql?((actual))です。Kernel.raiseやコアクラスのeql?を再定義するコード、at_exitハンドラーからプロセスを終了させるコード、brutalを見つけると振る舞いを変えるコードは、確認を変えてしまいます。Brutalは、それを打ち負かそうとするコードからは身を守りません。
  • タイムアウトはありません。終わらないコードは、brutalを待たせ続けます。中断されたbrutalは実行中のコードをkillし、それ以上何も書かずに、そのシグナルで終了します。
  • macOSでは、Objective-Cのクラスを使うコードが子プロセスでクラッシュすることがあります。その場合はOBJC_DISABLE_INITIALIZE_FORK_SAFETY=YESをつけてbrutalを実行してください。
