fix-command

fixコマンド。仕様ファイルごとにひとつのプロセスと、満たされたファイルの数。

fixコマンドは、fixの仕様ファイルをそれぞれ専用のプロセスで実行し、その結果をそのまま通して、満たされたファイルの数を伝えます。ファイルが満たされたとは、そのプロセスが0で終了したということで、ファイルの最後のexit(Fix[:Name].test { … })がそれを与えます。終了ステータスはサブジェクトが偽造できない唯一のものなので、コマンドはそれ以外のものを読みません。プロジェクト全体をこれで実行する方法は、ガイドの仕様を実行するにあります。

インストール

Gemfileにgem "fix-command"を加えるか、gem install fix-commandを実行してください。fixも一緒にインストールされます。

使い方

引数がなければ、fixはfixディレクトリ以下の任意の深さにある*_fix.rbファイルを実行します。Fixにとってのfix/は、minitestにとってのtest/です。引数があれば、与えたファイルを名前にかかわらず、与えたディレクトリの*_fix.rbファイルとともに、引数の順に実行します。ディレクトリの中のファイルは名前の順です。そうしたファイルを2つもつプロジェクトを例にとると、1つ目はfix/account_fix.rbです。

require "fix"

Fix :Account do
  on :balance do
    it MUST eq 100
    it SHOULD eq 200
  end
end

Account = Struct.new(:balance)

exit(Fix[:Account].test { Account.new(100) })

2つ目はfix/duck_fix.rbです。

require "fix"

Fix :Duck do
  on :quack do
    it MUST eq "Quack!"
  end

  on :swim do
    it MAY eq "Splash!"
  end
end

class Duck
  def quack = "Quack!"
end

exit(Fix[:Duck].test { Duck.new })

プロジェクトの中で、fixはそれぞれのファイルを、fixを実行しているRubyで新しいプロセスとして実行します。ファイルの出力はfixと同じところに書かれ、最後に件数が来ます。

fix
fix/account_fix.rb:5: Success: expected 100 to eq 100
fix/account_fix.rb:6: Warning: expected 100 to eq 200
fix/duck_fix.rb:5: Success: expected "Quack!" to eq "Quack!"
fix/duck_fix.rb:9: Info: NoMethodError: undefined method 'swim' for an instance of Duck
2 files met

満たされないファイル、読み込み時に例外を発生させるファイル、異常終了したプロセスがあると、2 files, 1 not met: fix/account_fix.rbとなり、終了ステータスは1になります。プロセスはコマンドの環境を受け継ぎます。bundle exec fixはすべてのファイルにGemfileのgemを与え、RUBYOPT=-Ilib fixはロードパスにlibを加えます。

ランダムな順序

プロセスに関する限り、ファイルの順序が結果を変えることはありません。各ファイルはひとつのプロセスで、各コンテキストはその子プロセスだからです。ただし、サブジェクトがプロセスの外で行うことは順序に左右されることがあります。ある仕様が変えたまま次の仕様に残していく、データベースやファイルです。--randomはファイルをランダムな順で実行し、最初に、同じ順でもう一度実行するためのコマンド--random=SEEDを書きます。

fix --random
fix --random=2
fix/duck_fix.rb:5: Success: expected "Quack!" to eq "Quack!"
fix/duck_fix.rb:9: Info: NoMethodError: undefined method 'swim' for an instance of Duck
fix/account_fix.rb:5: Success: expected 100 to eq 100
fix/account_fix.rb:6: Warning: expected 100 to eq 200
2 files met

終了ステータス

すべてのファイルが満たされれば0、満たされないものがあれば1、使い方の誤り、つまり未知のオプション、存在しないパス、実行するファイルがない場合は2で、標準エラーに使い方とともに書かれます。--helpは使い方を、--versionはバージョンを書きます。コマンドは結果の中身を何も読まないので、期待の件数も、色も、期待ごとの記号もありません。タイムアウトはなく、ファイルはひとつずつ実行されます。
