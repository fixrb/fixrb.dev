rspec-fix

値をFixの仕様でテストする、RSpecのマッチャー。

RSpec::Fixは、RSpecのexampleにfixという語を加えます。expect(value).to fix(:Name)は、値がfixの仕様のすべての期待を満たすときに成功し、満たさない期待は、メッセージに1行ずつ示されます。RSpecのテストスイートをそのまま残して、Fixの仕様を加えるための方法です。minitestにはminitest-fixがあります。

インストール

テストスイートのGemfileにgem "rspec-fix"を加え、fixをrequireするrequire "rspec/fix"を書き、RSpec.configure { |config| config.include RSpec::Fix }でexampleにこの語を与えてください。グループごとにモジュールをincludeすることもできます。

使い方

fix(:Name)はFix :Name do … endで登録された仕様を探し、なければKeyErrorを発生させます。テストスイートの中では、exampleはit { is_expected.to fix(:Duck) }と書けます。下のファイルは、exampleの語を自分に取り込んでいるので、テストスイートなしで実行でき、レポートのシード値や時間を含まない、マッチャーのメッセージだけを出力します。

require "rspec/fix"

Fix :Duck do
  on :walk do
    it MUST eq "Klop klop!"
  end

  on :swim do
    it SHOULD eq "Swoosh..."
  end

  on :speak do
    it MAY eq "Quaaack!"
  end
end

class Duck
  def walk = "Klop klop!"
  def swim = "Swoosh..."
  def speak = "Quaaack!"
end

class Robot
  def walk = "Klop klop!"
  def swim = "Glug glug..."
end

class RubberDuck
  def swim = "Swoosh..."
  def speak = "Squeak!"
end

# An example of RSpec has these words; here, outside a suite, the file takes them.
include RSpec::Matchers
include RSpec::Fix

expect(Duck.new).to fix(:Duck)  # => true
expect(Robot.new).to fix(:Duck) # => true

begin
  expect(RubberDuck.new).to fix(:Duck)
rescue RSpec::Expectations::ExpectationNotMetError => e
  puts e.message
end

ruby usage.rb
expected the value to fix Duck:
  usage.rb:5: Error: NoMethodError: undefined method 'walk' for an instance of RubberDuck
  usage.rb:13: Failure: expected "Squeak!" to eq "Quaaack!"

マッチャーは、WarningやInfoも含めてすべての期待が成功として扱われれば成功します。ロボットは、泳ぎ方が違い、鳴きもしませんが成功し、RSpecはそれについて何も伝えません。すべての行を出力するのはFix[:Duck].test { Robot.new }です。成功しなかったときは、FailureとErrorの行を、それぞれの期待の場所とともに示します。expect(value).not_to fix(:Name)は、期待がひとつでも満たされなければ成功します。RSpecのマッチャーと同じように組み合わせられます。fix(:Duck).and fix(:Bird)、コレクションの各値にはall(fix(:Duck))、ほかのマッチャーの引数としてはinclude(pet: fix(:Duck))。受け取るのは値で、ブロックではありません。値は一度だけ与えられるので、マッチャーのための仕様はwithなしで書きます。

exampleのプロセス

仕様のメソッドは、exampleのプロセスの中で、値そのものに送られます。そこにはexampleのトランザクションも、テストダブルも、カバレッジツールもあります。値を変えるメソッドは、続くコンテキストとexampleの残りの部分にとっても、その値を変えます。fix(:Name, fork: true)は、Fixと同じように、各コンテキストを子プロセスで実行します。メソッドは値のコピーに送られ、exampleが持っている値はそのまま残ります。これは、状態がすべてプロセスの中にある値のためのものです。プロセスの外にあるものはコピーされないからです。トランザクションを使うテストのRailsアプリケーションでは、子プロセスにはexampleが作った行が見えず、子プロセスが書いた行はロールバックされません。テストダブルには、子プロセスが受け取った呼び出しが見えません。
