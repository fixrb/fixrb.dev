matchi

フレームワークに依存しない、Rubyのマッチャー。

マッチャーは期待値をもって作られ、実際の値がマッチするかどうかを問われます。答えはtrueかfalseで、否定、メッセージ、レポートはテストフレームワークに任せます。

インストール

Gemfileにgem "matchi"を加えるか、gem install matchiを実行してください。

使い方

match?に与えたブロックは一度だけ呼ばれて実際の値を返し、to_sは「expected … to …」という文を完成させます。

require "matchi"

matcher = Matchi::Eq.new(42)
matcher.match? { 42 } # => true
matcher.match? { 41 } # => false
matcher.to_s          # => "eq 42"

マッチャー

Be
equal?による同一性。
Eq
同じクラスの値どうしの、eql?による同値性。
BeAKindOf
直接または名前で与えたモジュールの一種であること。
BeAnInstanceOf
直接または名前で与えたクラスのインスタンスであること。
BeWithin
期待する数値との差がデルタ以内のInteger、Float、Rational、BigDecimal。
Match
Regexpにマッチする文字列かシンボル。
Satisfy
ブロックがtrueと答える値。
Predicate
述語がtrueと答える値。:be_emptyはempty?を呼びます。
RaiseException
指定したクラスの例外を、必要なら指定したメッセージとともに発生させるブロック。Interrupt、シグナル、NoMemoryErrorは、それが期待したクラスでない限り素通りします。
Change
公開メソッドの戻り値を変えるブロック。必要ならby、by_at_least、by_at_most、to、あるいはfromとtoで指定します。

決めるのは期待値

マッチャーが期待値と実際の値を比べるとき、呼び出しを受けるのは期待値の側です。Matchi::Eq.new(a)はa.eql?(b)を評価し、決してb.eql?(a)は評価しません。自分の等価性について嘘をつく実際の値は、通ることができません。

require "matchi"

actual = "bar"

def actual.eql?(*)
  true
end

actual.eql?("foo") # => true

matcher = Matchi::Eq.new("foo")
matcher.match? { actual } # => false

3つの場合は、テスト対象のオブジェクトが生み出す値に、つまりその誠実さに頼ります。Predicateはそのメソッドのひとつを呼び、Changeのby系の指定はそれが返す値を比べたり引いたりし、RaiseExceptionのメッセージの条件は発生した例外のメッセージを読みます。どのマッチャーがどの保証を与えるかは、READMEに書かれています。

この規則の理由はテストにおける期待値と実際の値の根本的な違いにあります。

テストフレームワークとともに

どのフレームワークでも、数行でマッチャーを使えます。Minitestなら次のとおりです。

require "matchi"
require "minitest/autorun"

class TestAnswer < Minitest::Test
  def assert_matches(matcher, actual)
    message = "expected #{actual.inspect} to #{matcher}"
    assert matcher.match? { actual }, message
  end

  def test_answer
    assert_matches Matchi::BeAKindOf.new(Integer), 42
    assert_matches Matchi::BeWithin.new(0.01).of(0.3), 0.1 + 0.2
  end
end
