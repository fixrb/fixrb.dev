aw

Rubyのブロックを、forkしたプロセスで実行する。

ブロックが返したものは親プロセスに戻り、ブロックが発生させた例外は親プロセスで再び発生します。プロセスに対して行ったことは子プロセスの中にとどまります。変更、グローバル変数、定数、カレントディレクトリ、ENV、クラッシュなどです。外に対して、つまりファイルやほかのプロセスに対して行ったことは実際に起こります。Fixは仕様の各コンテキストをこうした子プロセスで実行し、brutalはマニフェストのコードを実行して戻り値を記録します。

インストール

Gemfileにgem "aw"を加えるか、gem install awを実行してください。WindowsやJRubyなどfork(2)のない環境では、Aw.supported?はfalseを答え、fork!とfork?はNotImplementedErrorを発生させます。

使い方

fork!はブロックが返したものを返し、fork?はブロックが例外を発生させずに値を返したかどうかを伝えます。リストが変わるのは子プロセスの中だけです。

require "aw"

list = ["foo"]

Aw.fork! { list << "bar" } # => ["foo", "bar"]
list                       # => ["foo"]

Aw.fork? { list.fetch(0) } # => true
Aw.fork? { list.fetch(1) } # => false

エラー

fork!は、ブロックが発生させた例外を、そのメッセージ、バックトレース、原因とともに親プロセスで再び発生させます。exitやabortのSystemExit、そしてTERMのように、Rubyが例外に変えるシグナルのSignalExceptionも含みます。捕捉しなければ、それらは子プロセスを終わらせたのと同じように親プロセスを終わらせます。

子プロセスが結果を届けないとき、fork!とfork?はAw::ChildErrorを発生させます。KILLのようなシグナルで終了した、子プロセスがexit!やexecを呼んだ、ブロックがbreak、return、throwで抜けた、あるいは親へのパイプを閉じた場合です。エラーのstatusは子プロセスのProcess::Statusです。

require "aw"

raised = begin
  Aw.fork! { Integer("forty-two") }
rescue ArgumentError => e
  e
end
raised.message # => "invalid value for Integer(): \"forty-two\""

failed = begin
  Aw.fork! { Process.kill(:KILL, Process.pid) }
rescue Aw::ChildError => e
  e
end
failed.status.signaled? # => true

値や例外はMarshalでパイプを通り、コピーとして戻ってきます。Marshalがダンプできないとき（Proc、IO、特異メソッドをもつオブジェクト、無名クラスのインスタンス、それらを保持するもの）や、親プロセスがロードできないとき（親が知らないクラスのインスタンス）も、fork!はAw::ChildErrorを発生させます。fork?はどちらも転送しないので、それらが戻ってこられない場合でも答えます。

制限

  • Awはサンドボックスではありません。信頼するコードがプロセスに加える変更を子プロセスの中にとどめるだけです。悪意のあるブロックはあなたのユーザー権限で実行され、fork!に何でも返させたり発生させたりでき、fork?にtrueと答えさせ、親プロセスのmarshal_loadメソッドやautoloadを実行させ、書いた分だけ親プロセスにメモリを抱えさせ、親にシグナルを送り、プロセスを残していくことができます。システムから来るのはAw::ChildErrorのstatusだけです。
  • Awにはタイムアウトがありません。fork!とfork?は子プロセスが終了するまで、そして結果が届かないときは、ブロックがexecせずにforkしたプロセスがすべて終了するまで待ちます。ブロックが終わらないおそれがあるなら、呼び出しをTimeoutで包んでください。中断された親プロセスは子プロセスに終了を求め、0.5秒後にまだ残っていればkillし、刈り取ってから先へ進みます。
  • ブロックがプロセスの外で行ったことは、元に戻りません。親プロセスが開いたファイルや接続はオフセットも含めて子プロセスと共有されるので、接続はブロックの中で開いてください。
  • 子プロセスに存在するのは、fork!やfork?を呼んだスレッドだけです。
  • 呼び出しのコストは数ミリ秒で、大きなプロセスほど増えます。50 MBで約2 ms、700 MBで20 msです。
