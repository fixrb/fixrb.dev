fix

Specifications in the words of RFC 2119, tested against a subject.

A specification says what a subject MUST, SHOULD or MAY do, in the words of RFC 2119, and nothing about how it is made. Any subject is then tested against it, each context in a child process, and every expectation gets a result. Fix is the main gem of Fixrb, built on spectus, matchi, defi and aw.

Install

Add gem "fix" to your Gemfile, or run gem install fix.

Usage

A file writes a specification, then tests a subject against it. Fix :Duck do … end builds the specification and registers it under its name; Fix[:Duck] finds it again. test builds a new subject with the block for every expectation, sends it the methods of the on around it, judges what comes out, writes one line per expectation and returns whether all of them pass; exit turns that into the status of the process.

require "fix"

class Duck
  def walk = "Klop klop!"
  def swim = "Swoosh..."
end

Fix :Duck do
  on :walk do
    it MUST eq "Klop klop!"
  end

  on :swim do
    it MUST eq "Swoosh..."
  end

  on :speak do
    it MAY eq "Quaaaaaack!"
  end
end

exit(Fix[:Duck].test { Duck.new })

ruby duck.rb
duck.rb:10: Success: expected "Klop klop!" to eq "Klop klop!"
duck.rb:14: Success: expected "Swoosh..." to eq "Swoosh..."
duck.rb:18: Info: NoMethodError: undefined method 'speak' for an instance of Duck

The duck has no speak: under MAY, a method the subject does not have is an info, which passes. Keep the parentheses of exit(…): exit Fix[:Duck].test do … end would give the block to exit.

Writing a specification

The block of Fix is a document, read once when the file is loaded, with four words. on :name, *arguments sends a method to the subject, and the expectations inside judge what it returns; an on inside an on sends its method to that value. let(:name) { … } is a parameter of the subject, a block the subject block calls, computed once per expectation; with name: value opens a context where the parameter has that value. it takes a requirement: a level, MUST, MUST_NOT, SHOULD, SHOULD_NOT or MAY, then a matcher.

require "fix"

Fix :Greeting do
  let(:name) { "Bob" }

  it MUST eq "Hello, Bob!"
  it MUST_NOT be_nil

  on :size do
    it MUST eq 11
  end

  with name: "Alice" do
    it MUST eq "Hello, Alice!"
  end
end

exit(Fix[:Greeting].test { "Hello, #{name}!" })

ruby greeting.rb
greeting.rb:6: Success: expected "Hello, Bob!" to eq "Hello, Bob!"
greeting.rb:7: Success: expected "Hello, Bob!" not to be nil
greeting.rb:10: Success: expected 11 to eq 11
greeting.rb:14: Success: expected "Hello, Alice!" to eq "Hello, Alice!"

A let is visible from the subject block and from the other lets only: named in an expectation, it raises NameError at load, with the remedy. Its name cannot be a method of the object the subject is built on, nor a word of the language, so that nothing is redefined in silence. The matchers are those of matchi, as words: eq, be, be_true, be_false, be_nil, be_within(delta).of, match, be_an_instance_of, be_a_kind_of, raise_exception, change, satisfy; and fix(:Name), since a specification is a matcher too. There is no predicate helper: on(:empty?) { it MUST be_true } asks the question.

Everything that is wrong in the document raises when the file is loaded, before any test: an it with a block or without a requirement, a let or a specification named twice, a matcher without match?. A block that raises registers nothing.

Outcomes

Two questions tell the levels apart. Does the method exist? MUST and SHOULD require it, MAY does not. Does it do what is specified? MUST and MAY require it, SHOULD recommends it. Hence five outcomes, of which a success, a warning and an info pass:

LevelMatch is trueMatch is falseMissing methodOther exception
MUSTsuccessfailureerrorerror
SHOULDsuccesswarningerrorerror
MAYsuccessfailureinfoerror

A negation swaps the first two columns. The missing method is the one named by the on of the context, when the object it is sent to raises NoMethodError for it. Below an error, test writes the frames of its backtrace that are not those of Fix and its gems:

require "fix"

class Account
  def initialize(balance)
    @balance = balance
  end

  attr_reader :balance

  def withdraw(amount)
    raise ArgumentError, "insufficient funds" if amount > balance

    @balance -= amount
  end
end

Fix :Account do
  on :balance do
    it MUST eq 100
    it MUST eq 200
    it SHOULD eq 200
  end

  on :currency do
    it MAY eq "EUR"
  end

  on :withdraw, 500 do
    it MUST eq(-400)
  end
end

Fix[:Account].test { Account.new(100) } # => false

ruby account.rb
account.rb:19: Success: expected 100 to eq 100
account.rb:20: Failure: expected 100 to eq 200
account.rb:21: Warning: expected 100 to eq 200
account.rb:25: Info: NoMethodError: undefined method 'currency' for an instance of Account
account.rb:29: Error: ArgumentError: insufficient funds
  account.rb:11:in 'Account#withdraw'
  account.rb:33:in '<main>'

Results

test writes, for each expectation, one line, LOCATION: OUTCOME: SUMMARY, the summary being that of spectus; that grammar is what a runner reads, with the status of the process. run gives the same results as data, in the order of the contexts, and match? tests a value as a matcher does:

require "fix"

Fix :Size do
  it MUST be_an_instance_of String

  on :size do
    it MUST eq 3
  end
end

results = Fix[:Size].run { "abcd" }
results.map(&:outcome) # => [:success, :failure]
results.map(&:passed?) # => [true, false]

result = results.last
result.location # => "examples/fix/results.rb:7"
result.chain    # => ".size"
result.summary  # => "expected 4 to eq 3"
result.to_s     # => "examples/fix/results.rb:7: Failure: expected 4 to eq 3"
result.result.class # => Spectus::Result

Fix[:Size].match? { "abc" } # => true

Processes

Each context with expectations runs in a child process, forked from the one that tests, with aw: a subject that leaves something behind cannot touch the next context, and what it raises, an exit included, is an error of its expectation alone. The contexts run one after the other, and the parent writes the results of a context as its child returns them. Nothing is rescued around a child: an Interrupt stops the run, and so does a child that died, with Aw::ChildError. Fix never writes a result that did not come from an expectation. test(fork: false) runs the contexts in the process itself, for a debugger.

Extensions

fix-its adds the word its, a method and its expectation on one line. matchi-fix brings a specification of Fix to any framework that takes a matcher of matchi. The block of Fix runs on an instance of Fix::Dsl, where a gem may add a word of its own.
