Coming from minitest

The same ideas under other names, and a few left out on purpose.

  1. Structure
  2. Assertions
  3. Three levels instead of skip

minitest writes a test as a method that builds an object, acts on it and asserts what came out. Fix splits that in two. A specification says what must come out, in a document that names no class and holds no code that runs before or after an expectation; the test, on the last line, gives the subject, so that the same specification can test another one. The page speaks of test classes and assertions; for minitest/spec, with describe and it, Coming from RSpec is closer.

A test class of a counter, with a setup, a test that increments it and another that builds it from another value:

require "minitest/autorun"

class Counter
  attr_reader :count

  def initialize(start) = @count = start
  def increment = tap { @count += 1 }
end

class CounterTest < Minitest::Test
  def setup
    @counter = Counter.new(0)
  end

  def test_count
    assert_equal 0, @counter.count
  end

  def test_count_after_an_increment
    assert_equal 1, @counter.increment.count
  end

  def test_count_from_five
    assert_equal 5, Counter.new(5).count
  end
end

becomes:

require "fix"

class Counter
  attr_reader :count

  def initialize(start) = @count = start
  def increment = tap { @count += 1 }
end

Fix :Counter do
  let(:start) { 0 }

  on :count do
    it MUST eq 0
  end

  on :increment do
    on :count do
      it MUST eq 1
    end
  end

  with start: 5 do
    on :count do
      it MUST eq 5
    end
  end
end

exit(Fix[:Counter].test { Counter.new(start) })

ruby counter_fix.rb
counter_fix.rb:14: Success: expected 0 to eq 0
counter_fix.rb:19: Success: expected 1 to eq 1
counter_fix.rb:25: Success: expected 5 to eq 5

The setup became the block of the test, and the value it gave the counter a let, which a with changes for one context. The call that came before the assertion became a method of the chain: increment returns the counter, and count is sent to it.

Three levels instead of skip

minitest skips a test with skip: it is counted apart, and its assertions do not run. Fix says it in the specification itself: SHOULD for what is recommended, a warning when it is not met; MAY for what is optional, an info when the method does not exist. Both pass, both run, and both are written in the lines, so nothing is hidden. Writing specifications has the five outcomes.

Left out on purpose

  • setup and teardown: the subject block builds what a subject needs, for each expectation, and each context runs in a process of its own, so there is nothing to clean up in memory.
  • Mocks and stubs, Minitest::Mock, stub: give the subject a real object, or a small object of the file that stands for a service, through a let. A specification says what a subject does, not which messages it sends.
  • Shared state between tests, instance variables, class variables: a let lives with one subject, and a context cannot reach another; only a with shares its value, within its context.
  • A random order of tests: minitest shuffles the tests to find those that depend on one another. The contexts of Fix run in the order written, each in its process, where the order cannot change a result; fix --random shuffles the files, which share what is outside the processes.
  • Custom messages, the last argument of an assertion: every expectation gets its line, with what was expected and what came out.

Both can live in one project, and a test of minitest can check a specification of Fix: Beside RSpec or minitest tells how.
